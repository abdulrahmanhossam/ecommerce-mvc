2.1 INTRODUCTION
--------------------------------------------------------------------------------

The frontend is the part of the application that users interact with directly.
For an e-commerce site, the frontend handles product browsing, shopping cart
operations, checkout, and account management. Research shows that 75% of users
judge a company's credibility based on its website design, and a one-second
delay in page load can reduce conversions by 7%.

ShopHub's frontend was built around three goals:

  1. Performance. Keep dependencies small, optimize assets, and render pages
     quickly on all devices.

  2. Accessibility. Use semantic HTML, ARIA attributes, keyboard navigation,
     and proper color contrast.

  3. Usability. Smooth transitions, consistent visual style, and dark/light
     themes make the site pleasant to use.

This section describes the frontend architecture, the design system, the
component library, the JavaScript functionality, the responsive layout, and
the admin panel.


2.2 FRONTEND TECHNOLOGY STACK
--------------------------------------------------------------------------------

  +---------------------+--------------------------------------------------+
  | Layer               | Technology                                       |
  +---------------------+--------------------------------------------------+
  | HTML Templating     | ASP.NET Core Razor Views (.cshtml)               |
  | CSS Framework       | Bootstrap 5 (vendored)                           |
  | Custom CSS          | site.css (design system + component styles)      |
  | JavaScript Core     | jQuery 3.x (vendored)                            |
  | Custom JS           | site.js (application logic)                      |
  | Validation          | jQuery Validation + Unobtrusive Validation       |
  | Icons               | Bootstrap Icons 1.11 (CDN)                       |
  | Charts              | Chart.js 4.4.0 (CDN, admin only)                 |
  | Typography          | Plus Jakarta Sans (Google Fonts)                 |
  +---------------------+--------------------------------------------------+

Technology choices:

  Bootstrap 5 gives a responsive grid system, reusable components, and utility
  classes. Its CSS variable architecture supports dark/light themes. The files
  are vendored locally so the site does not depend on a CDN at runtime.

  jQuery 3 is used because the jQuery Validation plugin needs it. The project
  has about 118 lines of custom JavaScript, mostly for AJAX calls and DOM
  manipulation.

  Bootstrap Icons provides over 1,900 SVG icons without needing JavaScript.
  Icons are used in navigation, buttons, status indicators, and decorative
  elements.

  Chart.js is a lightweight charting library used on the admin analytics page
  only. It loads from CDN, not from the global layout.

  Plus Jakarta Sans is a clean sans-serif font loaded from Google Fonts with
  preconnect hints for faster loading.


2.3 DESIGN SYSTEM
--------------------------------------------------------------------------------

2.3.1 CSS Custom Properties

The visual design is based on CSS custom properties defined in site.css. These
variables keep the look consistent across all components and make theme
switching easier.

    --space-md: 1rem;
    --space-lg: 1.5rem;

    --space-3xl: 4rem;

Using variables this way means:
  - All spacing, radius, shadow, and transition values are defined in one place
  - Switching themes only means overriding the variable values
  - The CSS file stays smaller because values are reused

2.3.2 Dark/Light Theme

The theme uses the data-bs-theme attribute which switches between "dark"
(default) and "light". This works with Bootstrap 5.3's built-in dark mode.

  [data-bs-theme="light"] {
    --bg-primary: #ffffff;
    --bg-secondary: #f8f9fa;
    --bg-card: #ffffff;
    --text-primary: #1a1a2e;
    --text-secondary: #6b7280;
  }

The theme preference is saved in localStorage, so it persists across page
loads and browser sessions. The default is dark mode. When toggling, the icon
switches between a moon icon (dark mode) and a sun icon (light mode).

2.4.2 Header

The header is fixed at the top with a glassmorphism effect using backdrop-
filter: blur(12px). It changes layout based on screen size:

  Desktop (>768px): Logo | Home - Categories - About | Search Bar | Actions
  Tablet (576-768px): Logo | Nav Links | Actions (no search bar)
  Mobile (<576px): Logo | Actions (with hamburger menu)

Navigation links detect the active page using a local function:

  bool IsActive(string ctrl, string action) =>
      currentController == ctrl && currentAction == action;

The active class and aria-current attribute are set based on this function.

2.4.3 Mobile Navigation

Below 768px, the desktop navigation is replaced by a slide-down menu triggered
by a hamburger button. The animation uses CSS transitions:

  .mobile-nav {
    max-height: 0;
    opacity: 0;
    overflow: hidden;
    transition: max-height 0.35s ease, opacity 0.25s ease;
  }
  .mobile-nav.open {
    max-height: 500px;
    opacity: 1;
  }

Using max-height instead of display: none allows the menu to animate smoothly.

2.4.4 Footer

The footer has a 4-column responsive grid:

  Column 1 - Brand: Logo, description
  Column 2 - Shop: Products, Categories, Cart, Wishlist
  Column 3 - Account: Login/Register, Profile, Orders, Contact
  Column 4 - Company: About, FAQ, Privacy, Terms

A bottom bar has copyright text and payment method icons. All links use
ASP.NET Core tag helpers (asp-controller, asp-action) for URL generation.

2.5.5 Star Ratings

  }

2.5.6 Variant Selection Cards

Product variants (size/color) are shown as radio-card selectors. The :has()
pseudo-class highlights the selected card:

  .variant-card:has(input:checked) {

    background: rgba(201, 162, 39, 0.1);
  }
  .variant-card:has(input:disabled) {
    opacity: 0.4;
    cursor: not-allowed;

2.6 JAVASCRIPT FUNCTIONALITY
--------------------------------------------------------------------------------

2.6.1 Custom JS (site.js)

The project has about 118 lines of custom JavaScript. The main functions are:

  getToken():
    Reads the anti-forgery token from the hidden input field. Used for all
    AJAX POST requests to prevent CSRF attacks.

  updateWishlistBtn(btn, isInWishlist):
    Switches the heart icon between outline (bi-heart) and filled
    (bi-heart-fill), and adds or removes the active class.

  toggleWishlist(productId, btn):
    Checks if the product is in the wishlist, sends the right AJAX request
    (add or remove), updates the button, and shows a toast.

  showToast(message, type):
    Creates a toast div with the message and type, appends it to the
    #toast-container, and sets a 4-second auto-dismiss timer.

  dismissToast(id):
    Adds the dismiss class to start the CSS transition, then removes the
    element from the DOM after the transition ends.

  markHelpful(reviewId, helpful):
    Sends an AJAX POST to /Products/MarkHelpful with the review ID and
    whether the user found it helpful. Updates the counter in the UI.

  checkWishlistStatus(productId):
    Called on page load for product detail pages. Checks the wishlist status
    via AJAX and updates the button accordingly.

2.6.2 Inline JavaScript in _Layout

The layout has inline JavaScript for global features:

  Theme Toggle (toggleTheme):
    - Reads the current theme from localStorage (defaults to "dark")
    - Sets data-bs-theme on the html element
    - Swaps the icon (moon <-> sun)
    - Saves the preference to localStorage

  Mobile Menu (toggleMobileMenu):
    - Toggles the .open class on #mobile-nav
    - The CSS transition handles the animation
    - Updates aria-expanded on the menu button

  AI Assistant Modal (openAIModal, closeAIModal, askAI):
    - openAIModal(productName, description): Shows the modal with product
      context
    - closeAIModal(): Hides the modal and resets the state
    - askAI(): Sends the product context and user question to
      /api/AIAssistant/ask using fetch(), shows a spinner while loading,
      then displays the response or error
    - Handles 429 rate limiting by reading the retry delay
    - Supports Enter to submit and Escape to close
    - Escapes HTML to prevent XSS

  Cart/Wishlist Counts:
    - On page load, fetches item counts via AJAX
    - Updates the badge text and removes the hidden attribute

2.7 RESPONSIVE DESIGN
--------------------------------------------------------------------------------

The layout uses mobile-first responsive design with these breakpoints:

  Breakpoint | Min Width | Target
  -----------|-----------|------------------
  Mobile     | 0         | Phones
  Tablet     | 576px     | Tablets
  Desktop    | 768px     | Laptops/Desktops
  Wide       | 1024px    | Large screens

Key responsive behaviors:

  Header: Desktop nav hidden on mobile, hamburger shown. Search bar hidden
  on tablets and below.

  Product Grid: 1 column on mobile, 2 on tablet, 3 on desktop, 4 on wide.

  Cart/Checkout: Single column on mobile, 2 columns on desktop (items left,
  summary right and sticky).

  Footer: 1 column on mobile, 2 on tablet, 4 on desktop.

  Admin Tables: Horizontal scroll on mobile via .table-responsive. Some
  columns are hidden on small screens.

  Forms: Full width on mobile, constrained on desktop for auth and checkout.

2.9 ACCESSIBILITY
--------------------------------------------------------------------------------

  ARIA Attributes:
    - aria-current="page" on active navigation links
    - aria-label on icon-only buttons
    - aria-expanded on dropdown toggles
    - aria-labelledby on modals
    - role="button" on interactive non-button elements

  Semantic HTML:
    - header, nav, main, footer landmarks
    - h1-h6 heading hierarchy
    - table with thead and th for data tables
    - form with label associations

  Keyboard Navigation:
    - All interactive elements are focusable and activatable
    - Escape closes the AI assistant modal
    - Focus-visible outlines on interactive elements

  Color and Contrast:
    - Text meets WCAG AA contrast ratios in both themes
    - Status uses icons and text, not just color

  Screen Readers:
    - Alt text on product and category images
    - Aria-live on the toast container for status announcements


2.10 PERFORMANCE OPTIMIZATIONS
--------------------------------------------------------------------------------

  Asset Loading:
    - Bootstrap vendored locally
    - Bootstrap Icons from CDN (non-blocking)
    - Chart.js loaded only on the analytics page
    - Google Fonts with preconnect hints
    - Version-tagged CSS/JS files for cache busting

  Images:
    - Lazy loading with loading="lazy"
    - Aspect ratio containment to prevent layout shifts
    - Admin uploads are resized on the server

  Rendering:
    - CSS transitions use only transform and opacity (GPU-accelerated)
    - Minimal layout thrashing with batched DOM operations

  JavaScript:
    - Only 118 lines of custom JS
    - AJAX for dynamic updates without page reloads
    - No heavy client-side frameworks (no React, Vue, or Angular)

Each view uses:

  - TempData for success and error messages
  - Tag helpers for URL generation and form binding


2.12 THEME TOGGLE
--------------------------------------------------------------------------------

The theme toggle works as follows:

  1. On page load, read the 'theme' key from localStorage. Default to 'dark'
     if not found. Set data-bs-theme on the html element.

  2. When toggled, switch between 'dark' and 'light', update the data
     attribute, swap the icon class, and save to localStorage.

  3. All component styles reference CSS custom properties, so the theme
     change propagates to every element automatically.

  4. The preference persists across page loads and browser sessions without
     any server-side storage.

2.13 AI ASSISTANT MODAL
--------------------------------------------------------------------------------

The AI Product Assistant is a global modal that can be opened from any page.
When opened from a product detail page, it includes the product context.

  Modal Structure:
    - Backdrop with blur effect
    - Centered modal card with a gradient header
    - Response area with four states: placeholder, loading (spinner),
      response, or error
    - Input field and send button at the bottom

  Interaction Flow:
    1. User clicks "Ask AI" on a product card or detail page
    2. The modal opens with the product name and description shown
    3. User types a question and presses Enter or clicks Send
    4. The question is sent to /api/AIAssistant/ask via fetch
    5. The server calls the Gemini API with the product context
    6. The response is displayed in the modal

  Error Handling:
    - Network errors show "Failed to connect"
    - 429 rate limit errors show the retry time
    - Empty responses show "No response"


2.14 SUMMARY
--------------------------------------------------------------------------------

The ShopHub frontend was built with ASP.NET Core MVC and standard web
technologies. Key results:

  1. All 42 views use zero inline styles. Everything is managed through the
     site.css design system.

  2. A CSS custom property system makes theming easy and keeps the visual
     style consistent.

  3. Dark/light theme support uses localStorage for persistence and CSS
     variables for propagation.

  4. The responsive layout works on mobile, tablet, and desktop using
     Bootstrap 5's grid system.

  5. Accessibility is handled with ARIA attributes, semantic HTML, keyboard
     navigation, and proper contrast ratios.

  6. Performance is optimized with minimal JavaScript, lazy images, GPU-
     accelerated animations, and efficient asset loading.

  7. The admin panel provides dashboard analytics, CRUD management for all
     entities, and Chart.js visualizations.

  8. The AI assistant integrates Google Gemini through a global modal,
     giving users product-specific help without leaving the page.

The frontend is designed to be easy to maintain. CSS custom properties
eliminate style duplication, Razor views provide compile-time checking, and
the MVC pattern keeps the code organized by responsibility.
